🏠 Loan Officer Portal

Runs on: operator.zillowhomeloans.com/loan-officer-portal

Pricing Exception Workflow

Loan toolbar — ⚖ Pricing Exception Workflow button (near Copy LOP file / Stage / Paste from staged)

Walks your manager's PE submission checklist end-to-end and hands you a ready-to-send email at the end.

  • Branched flow — first asks whether the loan is locked, then runs the right prerequisite checks (locked: import pricing → Comp PE fields → no lock-diff alert → Comp LE in eFolder; unlocked: scenario assigned → Comp LE on tasks → enter ZHL + comp pricing).
  • Auto-computes PE $ and points on the unlocked path: PE $ = (ZHL Box A − ZHL credits) − (Comp Box A − Comp credits); PE points = PE $ / loan amount × 100.
  • > 2.5 pts branch surfaces the three justification questions (reason for PE, borrower expectations, agent/partner relationship) and folds them into the email.
  • Auto-fills price / loan amount / rate / loan type from the Loan Details rail, plus ZHL Box A and lender credits scraped from the Total closing costs popup. RM email auto-saves and pre-fills next time.
  • Email output with editable subject + body, Open in Gmail (Gmail compose URL, not your OS mail client), and Copy body / Copy subject buttons.

Print Buyer Worksheet

Pricing results / eligibility table — button in each LTV section header

Check one or more rows in a section, click the button, and a borrower-facing handout opens in a new tab — one scenario per page, Zillow-blue branded, auto-fires the print dialog.

  • Two big numbers up top — Estimated monthly payment + Estimated cash to close — the figures buyers actually anchor on.
  • Clean details list — purchase price, down payment, loan amount, rate, points (plain-English "lender credit of $X" vs "cost of $X"), closing costs, breakeven. DTI is intentionally left off a borrower handout.
  • 3 scenarios per page so you can hand the buyer a side-by-side of the rate options you're discussing.
  • Pick Save as PDF in the print dialog, or send straight to the printer.

VA + non-spouse co-borrower warning

Full application — sticky banner across the top

Catches a common VA underwriting error before it ships: a non-veteran co-borrower who isn't the veteran's married spouse.

  • Fires when the product is VA, one borrower is a qualifying veteran (Regular military / National Guard or reserves), another borrower is non-veteran, and any borrower isn't marked Married.
  • Hard to miss — sticky red banner plus a red outline on the offending Veteran type and Marital status fields (same visual language as the FHA Non-Permanent Resident Alien warning).
  • Auto-clears the moment you fix it: change the product off VA, set the co-borrower to a qualifying veteran type, or mark both borrowers Married.

Hard Pull Guardrail

Full application — Pull Credit dialog, when Hard is selected

Catches accidentally-too-early hard pulls before they happen. Reads the worst soft qualifying score across borrowers + the most recent non-error DU result against ZHL’s guidance matrix; if the combination indicates a soft pull should be used instead, the click on Pull credit is intercepted and a confirmation dialog surfaces.

  • Fires when the soft score is greater than 620 and DU shows approval — outside the 680–719 LLPA optional-pricing window (reaching for the 700 / 720 tier improvement).
  • Shows the full matrix in the confirmation dialog so the LO can see exactly which row their loan lands on.
  • Not a hard stop. The dialog has two buttons: Cancel (keeps Pull Credit open) or Proceed with Hard Pull anyway (re-fires the click bypassing the guardrail).
  • If the score / DU combination is within guidance, nothing fires — Pull Credit behaves exactly as it did before.

Scenario Snapshot

Pricing & Scenarios → Scenarios — Snapshot button under each scenario card

Captures every field on a scenario card in one clean, single-viewport modal — designed for the moment an LO needs to attach scenario detail to an app-support ticket and would otherwise have to scroll and stitch multiple screenshots.

  • Single-screen capture. Every label / value row from the card lined up in one readable list, plus the title, Purchase / Refi subtitle, ASSIGNED TO LOAN / RE-PRICE status, and Priced: timestamp at the top.
  • Print opens a print-formatted new tab and auto-triggers the print dialog — save as PDF for the ticket attachment or send straight to a printer.
  • Copy as text writes a plain-text version of the snapshot to the clipboard with labels padded into fixed columns — paste cleanly into a Slack code block or a ticket body.

Send VPA Email from Salesforce

Salesforce Lead / Contact page action bar — Send VPA Email button (activates on the Pre-Approval stage)

One-click pre-filled Gmail draft for the standard Verified Pre-Approval congratulations email. Folds the standalone SFGmail proof-of-concept into the main toolkit with no Connected App and no per-user OAuth enrollment.

  • Scrapes the page for you. Borrower name, email, purchase price, co-borrower, and Buyer’s Agent — pulled straight off the Lead / Contact layout. Co-borrower and agent emails are extracted by triggering the SF hover preview card and reading the mailto link it surfaces.
  • Pre-fills the whole draft. Gmail compose opens in a new tab with To = borrower, CC = co-borrower + agent, Subject = “Congratulations — You’re Pre-Approved at Zillow Home Loans”, and the standard VPA body populated with the borrower’s name and purchase price.
  • No OAuth, no Google verification, no test-user cap. Uses the public Gmail compose URL (mail.google.com/mail/u/0/?view=cm&fs=1&…) instead of the Gmail API. Rollout is just flipping the Setup toggle — no Connected App setup, no Google Cloud project, no scopes to approve.
  • Attach the VPA PDF manually before sending. The compose URL approach can’t carry attachments, so the LO drops the pre-approval letter into the draft the same way they would for any other email. Everything else is filled out.

Send Intro Email from Salesforce

Salesforce Opportunity action ribbon — Send Intro Email button

One-click pre-filled Gmail draft for the “disclosures signed — here’s what happens next” introduction email to the borrowers. Sits in the same action-ribbon slot as Send VPA Email but on the Opportunity record instead of the Lead.

  • Scrapes the Opportunity for you. Borrower + co-borrower (name + email) come from the Contact Roles related list; Close Date and Loan Number come from the highlights panel. Property Address is grabbed too when it’s visible; if it isn’t, the placeholder stays in brackets for you to fill in.
  • Pre-fills the whole draft. Gmail compose opens with To = borrower, CC = co-borrower (when present), Subject = “Disclosures signed — here’s what happens next”, and the full HTML body populated from the customizable template — three numbered steps (initial UW review, processor intro, homeowners insurance), the homeowners insurance agent block (Karson Carter / Goosehead by default), your signature with NMLS, and the Borrower Information summary block at the bottom.
  • Editable from Setup. Setup → Send Intro Email from Salesforce → Intro Email template lets you customize the subject and the body. Same placeholder chips as the VPA editor ({First Name}, {Borrower Name}, {Co-Borrower Name}, {Property Address}, {Loan Number}, {Closing Date}, {LO Name}, {LO Email}, {NMLS}). Reset to default brings the original template back.
  • No OAuth, no Connected App. Uses the public Gmail compose URL + the Gmail companion content script for the auto-HTML-paste — same pattern as the VPA email and Pricing Exception Workflow.

MOSS Request from Salesforce

Salesforce Lead / Contact / Opportunity action ribbon — MOSS Request button (next to Send VPA Email)

One-click submission to the Mortgage Origination Support Specialist team. Pick the type of help you need from a short list, add a note or a due time, and the request lands directly in MOSS’s Work Discovery queue — no more “LO writes the same Slack DM ten times a day” pattern.

  • Coming soon: currently in scoping with the MOSS team and the Work Discovery team. Blocked on the LO-side intake endpoint — once that’s live, the button shows up here automatically with no extension reinstall.
  • Request types being scoped: look up condo report, work up a contract, call this buyer at a specific time, initial outreach, schedule the buyer on my calendar, work up a pre-approval, update a pre-approval, plus a free-form custom note.
  • Captures the borrower context for you. Record ID, borrower name, type of request, optional time and notes — MOSS sees the whole picture without you re-typing the basics.

Generate Loan Story for Encompass

Full Application subnav — Generate Loan Story for Encompass button (activates after a hard credit pull)

Drafts the five Encompass ZG-Loan-Story sections from this file in one click. Removes the re-typing cycle where the LO writes the same handful of facts into Encompass on every loan.

  • Five editable textareas, one Copy button each. Property Notes, Borrower Notes, Employment / Income Notes, Asset Notes, and Credit Notes — matched to the five Encompass fields. Edit the auto-draft before copying or rewrite it entirely; the modal doesn’t commit anywhere, it just hands you text.
  • Activates only after hard credit is pulled. The button stays disabled until LOP shows hard scores on the file — tooltip explains why. Keeps the tool from being run on incomplete files where most of the loan story doesn’t exist yet.
  • Auto-surfaces what processors care about: property type / PUD / construction, FTHB from Declarations, current and prior employment with start/end dates, gift fund totals and sources, liabilities the LO has marked for payoff or excluded from DTI, and callouts when collections handling or student-loan calc method needs to be confirmed.
  • Type-over friendly. The pieces the file can’t tell us — main point of contact, specific loan goals, non-borrowing spouse, variable-income calc method — are exactly the kind of context the LO already knows. The modal makes it cheap to add them and ship the whole story to Encompass in one paste cycle.

ZHL Loan Comparison PDF

Pricing & Scenarios → Scenarios review — ZHL Comparison PDF button next to Generate PDF

Generates a borrower-facing comparison PDF for every selected scenario via the browser's native Save-as-PDF flow.

  • Mirrors LOP's standard comparison with a few changes: Seller credit on its own line, Credit score and DTI rows dropped, and Estimated monthly cost (PITI) + Cash (to)/from rendered bigger and bolder.
  • Page 2 cost summary per scenario — monthly cost split into P&I vs taxes/insurance/escrows, plus total closing costs, seller credit applied, net closing cost, down payment, and final cash to close.
  • Pick Save as PDF in the print dialog, or send straight to the printer.

Max purchase price estimator

Pricing & Scenarios — pill in the Eligibility Details row

Shows the estimated max purchase price that would push back-end DTI to its program cap — Conv 49.99%, FHA 56.99%, VA 60%.

  • One pill per priced loan type, side-by-side.
  • Reads the current scenario's PITI and back-end DTI plus monthly income and liabilities, then back-solves the price assuming taxes / HOI / MI scale linearly with purchase price (accurate to within 1–2%).
  • Hover the pill for the math behind it.

Add Co-Borrower to Salesforce

Full application — button next to the co-borrower's Resend Link

One click takes the co-borrower from LOP into a Salesforce New Contact, so you don't re-type their details.

  • Reads the co-borrower's first name, last name, cell phone, and email from the Full Application page.
  • Switches to your open Salesforce tab, confirms the lead matches the primary borrower, clicks New Contact, and fills the form — with Role = Co-Borrower (Company auto-fills from the name).
  • Stops before saving — the filled modal is left on screen for you to review and click Next / Save. Nothing is written to Salesforce automatically.
  • If no Salesforce tab is open or the lead doesn't match, you get an inline message and nothing changes.

Bulk-download completed-task documents

Tasks tab → next to the Completed heading

One click downloads every borrower-uploaded document on the file. Walks every Zillow Docs link in the Completed tasks table, opens each one in a background tab, clicks the viewer's Download button, then closes the tab — sequential, one at a time, so the browser only prompts once about multiple downloads.

  • Live progress modal shows the current document name + task name + progress bar.
  • Summary at the end lists every downloaded file with its task name so you can rename / sort them after.
  • Files keep Zillow Docs' filenames (V8663-Regular.pdf, etc.) and land in your default Downloads folder — same as clicking Download manually.
  • Manual opens are safe. The zillowdocs-side helper is armed-flag gated, so opening a document on your own never triggers the auto-click — only this feature's bulk flow can arm it.

Net Proceeds from Sale calculator

Trigger: click the 🏠 Net proceeds calc button next to the Add asset or credit button in the Assets section on LOP's Financial Information page.

  • Six inputs. Sale price, Listing agent fee % (default 3%), Buyer's agent fee % (default 3%), Closing costs $, Mortgage/Loans/HELOC payoffs, and Other.
  • Closing costs auto-fill at 1% of the sale price the moment you type it — the moment you edit the closing-costs field manually, the auto-sync stops so your override sticks.
  • Live computed net proceeds with a per-line dollar breakdown. Output goes green for positive, red for negative.
  • Copy summary button puts a plain-text breakdown on your clipboard so you can paste it into notes, Slack, or a borrower email.
  • Last values are kept in localStorage on this tab so you don’t lose them if you close the modal accidentally.

Copy LOP file (whole-loan Stage & Paste)

Full application → floating "Copy LOP file" bar (top-right)

One click copies almost everything from a source LOP loan into a brand-new one. On the source loan, click Stage from this file — the extension reads every editable Personal info / Contact / Marital / Military / Declarations / Demographics field, every Address / Employment / Other income / Asset / Gift / Real estate row, plus per-liability metadata (Payoff / Exclude+Reason / Property link). It also opens each Real Estate and Liability row to grab form-only fields LOP doesn't show in the table (Property type, Current occupancy, Pending-sale date, etc.) and captures the source's credit pull type + CoreLogic reference ID. On the new loan, click Paste from staged and pick which stored loan to fill from.

  • Multi-borrower files auto-add the co-borrower: if the source has more borrowers than the destination, paste clicks the + tab → fills the Add-a-new-borrower dialog → clicks Create borrower before any fields land, so co-borrower data never ends up on the wrong section.
  • Saves the file then runs credit automatically: Hard pulls run Reissue with the staged reference ID; Soft pulls fire Choose action → Pull credit report. Liability edits (Payoff / Exclude+Reason / Property link) apply right after the credit pull populates the dest liabilities.
  • Self-bypasses LOP's credit-eligibility cache: when a co-borrower was just auto-added, paste reloads the page after save so LOP's credit cache picks up the new consent — credit then fires automatically once the page comes back.
  • Read-only / locked-in-this-file fields are skipped cleanly with a per-field report in the summary modal, so it's clear what the LO needs to finish manually.
  • Each stage persists in chrome.storage and stays usable across LOP tabs — no need to keep the source tab open.

Tip: this is the longest-running feature in the pack — the progress overlay shows what step it's on (Reading rows · Adding co-borrower · Paste pass · Saving · Refreshing · Resuming credit).

Copy addresses primary → co-borrower

Full application → Addresses → empty co-borrower section

One click re-adds every address on the primary borrower's list for the co-borrower. Picks each address via LOP's built-in "Use existing address" dropdown, then fills the fields LOP leaves blank: address type, housing type, dates, monthly rent, and the "Mailing same as current" checkbox.

  • Confirm prompt only if the co-borrower already has rows (prevents accidental duplicates).
  • Works for files with 3+ borrowers — the button appears on every co-borrower section.

FHA Manual Underwrite eligibility pill + Analyzer

Full application → Credit section

Reads the three bureau scores for each borrower, takes the middle, then uses the LOWER middle across borrowers. Shows green ✓ when ≥ 640, red ✗ when below.

Click the Analyze Manual UW button next to the pill for the full workup — it reads DTI, PITI, total assets, current rent and the unit count from the page, evaluates every ratio tier (31/43, 37/47, 40/40, 40/50) and compensating factor with ✓ / ✗ / ? indicators, and recommends the strongest tier you qualify for.

  • Auto-evaluated: min score, max DTI, ratio tiers, cash reserves (assets ÷ PITI), minimal-increase-in-housing-payment ($100 or 5% rule).
  • Manual checkboxes for the rest: significant additional income, VA residual, no discretionary debt, Energy Efficient Home — your selections persist while you're on the loan.
  • Hover the pill (without clicking) to see the full ZHL guideline matrix as a quick reference.
  • VA loans: the pill and analyzer switch automatically to VA Manual Eligible / Ineligible at a 660 floor, with a VA-specific analysis (660 score, 43% DTI, residual income via the VA table — 120% when DTI > 41%) plus VA Handbook Ch. 4 + guaranty confirmations. No FHA ratio tiers or investor score overlays on the VA path.

FHA Collections + Disputed badges ($2k / $1k caps)

Full application → Liabilities

Live cumulative-balance badges that flag when the file approaches FHA's $2,000 collections cap or $1,000 disputed-derogatory cap.

  • Reads liabilities through the React-fiber bridge — no need to expand each row.
  • Excludes medical collections (counted separately by FHA), charge-offs (don't count toward either bucket), and zero-balance rows.
  • Detects "ACCT IN DISPUTE" in the Remarks field — LOP's structured dispute flags are never populated in practice.

FHA + Non-Permanent Resident Alien warning

Full application — any page

Sticky red banner across the top whenever the loan is FHA AND any borrower's citizenship is Non-Permanent Resident Alien. HUD removed NPRAs from FHA eligibility on May 25, 2025 — this catches the combo before it ships to underwriting.

FHA 90-Day Property Flip Rule checker

Full application → right rail, under Loan Details (FHA loans only)

Computes the days between the seller's acquisition date and the contract date, then tells you which FHA flip tier the file falls under.

  • ≤ 90 days — red ×, NOT eligible for FHA insurance.
  • 91–180 days — amber, eligible but a second appraisal may be required if the resale price is ≥ 100% over the seller's purchase.
  • > 180 days — green ✓, no flip restriction.
  • 🔎 Look up on Zillow button opens a new tab searched for the property so you can grab the prior sale date from the price-history table, then paste it back into the card.

VA Residual Income + Student Loan Calc

Full application → Liabilities (per borrower pair)

Run Residual Income Calc reads income, debts, PITI, family size, and state, then shows residual vs. the VA table requirement with editable Non-Taxable / Maintenance & Utilities / Childcare rows.

Calc Student Loans fills monthly payments on student-loan liabilities that have no payment listed using FHA / DU / LPA / VA formulas. Now recognizes CENTRAL RESEARCH (the default-collection agency for defaulted federal loans) too.

VA Entitlement Calc (button beside Run Residual Income Calc) takes the entitlement the veteran has already used and shows the max loan with $0 down, plus the down payment required above that. County loan limit auto-fills from the property ZIP (2026 FHFA table, all high-cost counties + 1–4 unit), with a county dropdown + editable override for anything the ZIP doesn't pin down.

Meeting Reminders — Outlook-style pop-ups

Gmail (any view) — reads from any open calendar.google.com tab

Brings back the Outlook reminder window you miss: a card slides into the corner of Gmail before each meeting, with Snooze and Dismiss.

  • What you have to do: keep Google Calendar open in a tab (any view — Day, Week, or Month works). The extension reads events directly from the Calendar tab’s DOM, so closing every Calendar tab pauses reminders until you reopen one.
  • Why not a background fetch? Zillow Workspace disables per-user “Secret address in iCal format”, and the public iCal feed would expose borrower info. Reading from an already-open Calendar tab is the only zero-auth, zero-exposure path.
  • Reminders fire at each lead time you set — default 30 minutes and again at 5 minutes before start. Configurable in Setup, e.g. 30, 10, 2.
  • Snooze brings it back after the interval you pick; Dismiss / Dismiss all clears it. Choices sync across all your open Gmail tabs.
  • A 📹 Join button shows when the event has a Google Meet link. All-day events are skipped.

Appraisal Blast — one-click email all parties

Reggora "Appraisal Submission Summary" emails

When a Reggora Appraisal Submission Summary email is open, a gold “Send to all parties” button appears bottom-right. One click:

  • Parses the loan number, last name, address, appraised value, purchase price, and condition from the email.
  • Opens a hidden Salesforce tab, searches the loan, opens the Opportunity, and scrapes every Contact Role. Tab closes automatically.
  • Opens a new Gmail compose with TO = Borrower / Co-Borrower / Buyer’s Agent / Transaction Coordinator and CC = Processor.
  • Body is congratulatory (with immediate equity figure) for normal appraisals; switches to a low-value variant if the appraisal came in under purchase price or Reggora flagged it.

Nothing sends automatically — you review and hit Send. Your Gmail signature appends as normal. Requires you to be signed in to your Zillow Salesforce session.

☁️ Salesforce

Runs on: *.lightning.force.com, *.my.salesforce.com, Genesys Cloud

Mark All As Read

Salesforce Messaging panel → header (next to "New thread")

One-click button that walks every unread thread in the inbox, opens each (which is how Salesforce stamps a read receipt), then clicks Back to return. After the run, every thread is unbold and the unread counts are gone.

  • Detects unread via bold subject text, the right-side unread-count pill, or the unread class on the row.
  • Heavy console logging at every step — failure modes are debuggable without round-tripping for a new build.

Caller ID badge on inbound calls + voicemails

Salesforce console, Genesys Cloud embedded panels

When a phone number appears in the UI (inbound call, voicemail, call history row), the extension queries Salesforce for a matching Contact / Lead / Loan and stamps a blue pill with the borrower's name next to the number. 5-minute lookup cache so popular numbers don't hit the API repeatedly.

SMS quick-add: Co-Borrower / Buyer's Agent

Salesforce SMS panel → New thread

One-click buttons that look up the Co-Borrower's and Buyer's Agent's phone numbers from Salesforce and add them as participants to the SMS thread — no copy/paste from the Contact record.

Open SMS button on Contact records

Salesforce Contact / Lead record pages

Adds an Open SMS button next to the phone number that jumps straight into the messaging panel with that number pre-filled.
